# 跟奏与节奏记录

## 智能跟奏

原实现只尝试当前目标，漏识别后会持续等待；频谱中出现新分量或某分量变强也可能重新打开起音门，误把延音当下一音。

现在一次新起音最多确认一个谱位。确认后锁住已听到和谱面预期的组成音；和弦逐渐变弱、只剩一个组成音或后冒出的高次分音均不作为新起音。重新拨弦需整体音量起伏和目标音分量更新；击勾弦可通过新的主导音高变化推进。门控有有限时窗，不能被一次无关声音永久解锁。

搜索当前及后续 4 个谱位，若后面的目标稳定匹配，可跳过漏识别的目标并提示重新定位。不会因为长时间没声音就盲目前进。全为延音线的事件与休止不要求新起音，按谱面时值计时。

## 节拍跟随

独立的第三种模式。仍使用 AudioContext 时钟和前瞻调度，节拍器按设定 BPM 连续运行；检测结果不改变节拍速度或位置。示范音关闭，麦克风只用于匹配。

- 紫色播放线/目标：当前节拍对应谱位。
- 绿色框：最近检测到的弹奏谱位，文字显示小节、拍点及偏差。
- 每个谱位在节拍附近寻找匹配，已确认的起音不会重复消费。漏识别的音到期后标记“未识别”，后续目标仍可匹配。
- 偏差使用起音时间，扣除稳定音高确认等待时间及用户设置的输入延迟补偿。±80 ms 内记为合拍，负值为提前，正值为拖后。
- 暂停、结束、跳转、切换模式或速度时结算已经经过的部分；循环每遍单独记录。预备拍内取消不会保存空白记录。
- 最近 5 次记录仅保存在浏览器本地，可选择历史记录、导出 JSON。不保存或上传麦克风录音。

建议使用耳机，否则节拍声也可能进入麦克风，尤其会影响无音高拍击的识别。输入链路、蓝牙输出和频谱窗会带来延迟；在「记号 / 音色」里可设置输入延迟补偿（正值会减去检测延迟，需暂停后重新开始）。这是相对于固定节拍的估计，未经设备校准不能视为毫秒级测量。弱击勾弦、密集快速音符、多声部、重复乐句仍有识别歧义；“未识别”不意味着弹错或没弹。

## 验证

单元测试覆盖残留分音、和弦衰减、无关起音、同音重拨、漏音重定位、重复音候选锁定、提前/拖后分类、延迟补偿、休止/延音线和部分记录。浏览器测试将合成演奏通过 MediaStream 输入真实 AnalyserNode，验证预备拍、连续节拍、提前/拖后/漏音后的恢复、位置标记、保存/导出、静音结束、循环、跳转、变速暂停及手机布局。另保留已有虚拟麦克风曲目和弦与持续单音测试。合成输入测试不等价于所有真实麦克风及吉他环境验证。

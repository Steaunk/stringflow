# Stringflow · 六线谱练习室

一个纯静态的吉他练习网站：按节拍播放、听着你的演奏推进六线谱，以及根据谱面定弦与变调夹信息调音。界面支持桌面与手机，曲谱随网站打包，音频与练习记录在浏览器本地处理，不需要后端、数据库或上传服务。

![练习室界面](docs/desktop.png)

## 本地运行

建议 Node.js 24 LTS。

```sh
npm ci
npm run dev
```

打开 `http://localhost:5173`。麦克风需浏览器授权，并要求 **HTTPS 或 localhost**。在手机上通过局域网 HTTP IP 打开时，通常无法调用麦克风；请为手机测试配置 HTTPS。

```sh
npm run build       # 类型检查 + 生成 dist/
npm run preview     # 本地预览生产构建
npm test            # 音高、跟奏状态、内置曲谱校验测试
npx playwright install chromium
npm run test:e2e    # 浏览器测试，包括合成 WAV 麦克风输入
```

## 静态部署与 GitHub Pages

`npm run build` 生成根路径部署产物；`npm run build:site` 生成 `/stringflow/` 子路径部署产物。构建结果均在 `dist/`，只需要静态文件托管服务，无后端或数据库。

GitHub Pages 的项目站点地址为 `https://<owner>.github.io/stringflow/`，可由名为 `stringflow` 的独立仓库发布，无需复制到个人主页仓库。`.github/workflows/pages.yml` 在推送 `main` 时自动发布：完成检查、构建和测试后，仅上传 `dist/`，检查失败时不发布。其他分支和 Pull Request 运行独立 CI 检查。也支持手动重新发布。设置方法：

1. 在仓库的 **Settings → Pages → Build and deployment → Source** 选择 **GitHub Actions**。
2. 推送到 `main` 即自动检查并发布。需要手动重发时，在 **Actions → Publish GitHub Pages → Run workflow** 选择 `main`。以工作流返回的地址为准。

GitHub Free 账户的 Pages 使用公开仓库；支持私有仓库 Pages 的账户方案可保留源码私有。项目站点可能继承个人主页的自定义域名。参见 [GitHub Pages 文档](https://docs.github.com/en/pages/getting-started-with-github-pages/what-is-github-pages)及[自定义工作流](https://docs.github.com/en/pages/getting-started-with-github-pages/using-custom-workflows-with-github-pages)。

子路径构建使用 `npm run preview:site` 预览。应用中的资源、首页链接和曲目查询参数均支持 `/stringflow/`。GitHub Pages 的 HTTPS 可满足麦克风所需的安全上下文，仍需浏览器授权。

## 数据与许可

网站没有外部字体、统计脚本或上传接口。麦克风音频只在浏览器内分析；播放偏好、排版偏好和最近五次练习记录只保存在本机。原始谱面扫描件、第三方教学影音和开发环境配置不包含在发布产物中。

当前未指定代码开源许可证；公开仓库与授予开源使用许可是不同的决定。内置第三方曲目保留作品及编配署名，其权利不由项目代码许可证授予。`package.json` 的 `private: true` 只防止 npm 发布，与 GitHub 仓库可见性无关。[GitHub 许可证说明](https://docs.github.com/en/repositories/managing-your-repositorys-settings-and-features/customizing-your-repository/licensing-a-repository)。

## 使用

- **节拍播放**：30–240 BPM、0/1/2 小节预备拍、独立的节拍器和合成示范音、暂停与回到起点。BPM 以四分音符为单位；拍号和每个音的时值取自谱面。
- **谱面**：全宽排版，默认收起曲库；选曲后自动关闭。每行可选 3 / 4 / 5 小节并在本机记住，窄屏自动减少列数。支持标准 / 放大和专注视图，调音器独立打开。音符、拍线与拍号共用时间轴，显示符干、八分/十六分/三十二分符杠、附点及休止。
- **自动滚谱**：播放线沿拍点移动，播放进入可见区域倒数第二行时，将当前行移到顶部，提前显示后续谱面，点击音符或小节编号立即从该处播放（跳过预备拍），支持指定小节循环；点击循环范围外会退出循环。空格默认开始/暂停播放，点击模式、速度按钮或谱面后仍有效；长按只切换一次。输入框、下拉框、曲库抽屉和调音器弹窗保留原生键盘操作；修改速度或循环范围会暂停，点击播放继续。
- **演奏技法**：显示击勾弦弧线、滑音斜线（含跨小节连接）、扫弦方向、逐拍 P.M.、拍琴身与拍弦。播放使用同弦连奏、连续音高滑动、逐弦错开的扫弦和独立的打击声模型。
- **智能跟奏**：打开麦克风，弹出高亮目标音，匹配稳定后推进。支持单音、分解和弦与整和弦；整和弦按最低目标音及多数目标音级匹配，独立拍击按新起音推进，休止按设定速度计时。持续的和弦不会直接消费后续组成音，需要重新拨弦；击勾弦等音高变化可连续推进。漏识别后可在后续 4 个谱位重新定位，同一声延音只消费一次；延音线不要求重新拨弦。谱面上显示等待目标、检测音高和输入音量，仍可手动“跳过”。
- **随谱调音**：点击顶部“调音器”打开独立面板，关闭时释放麦克风。根据六根弦的定弦检测音名、频率和 cents 偏差。可自动选择最近的弦，或点击弦锁定。提供 Standard、Drop D、DADGAD、Open G，内置曲目也可自带特殊定弦。
- **节拍跟随**：节拍器按设定 BPM 持续前进，麦克风识别独立标出弹奏位置。紫色是节拍，绿色是检测位置；偏快 / 偏慢 / 合拍 / 未识别直接以橙 / 红 / 绿 / 灰色标在对应音符上，暂停后保留；谱面上方可切换历史或隐藏标记，最近 5 次保存在本机，可导出 JSON。建议戴耳机，避免节拍器串入输入。谱面底部「记号 / 音色」可调整输入延迟补偿。
- **变调夹**：默认取下变调夹调空弦，再夹到谱面指定品位。若已夹好，可勾选“按夹后空弦调音”。播放与跟奏始终计入变调夹移调。
- **内置曲库**：内置三首原创练习曲，以及内置的 [Something Just Like This](docs/something-just-like-this.md)（CGDGAD、Capo 5、112 BPM、101 小节）。不提供曲谱导入或编辑；保留 JSON 导出，并在本机记住内置选曲、速度偏好、每行小节数与最近 5 次练习记录。新增或修改曲目需更新源码并重新构建。

智能跟奏时示范音和节拍器静音，以避免声音被麦克风误认。启动调音会暂停播放；播放参考音会关闭麦克风，可在听完后重新开启。页面进入后台时自动暂停并释放麦克风。

## 内置曲谱数据（开发维护）

以下格式用于源码中的曲目维护与 JSON 导出，网页不提供文件导入。JSON 支持精确时值、休止、和弦、自定义定弦与拍号：

```json
{
  "version": 1,
  "title": "Drop D 练习",
  "artist": "我",
  "bpm": 80,
  "timeSignature": [4, 4],
  "tuning": [38, 45, 50, 55, 59, 64],
  "capo": 2,
  "events": [
    { "beats": 1, "notes": [{ "string": 6, "fret": 0 }] },
    { "beats": 0.5, "notes": [{ "string": 4, "fret": 2 }] },
    { "beats": 0.5, "notes": [] },
    { "beats": 2, "notes": [{ "string": 3, "fret": 0 }] }
  ]
}
```

`tuning` 为 **6 弦 → 1 弦（低音 → 高音）** 的空弦 MIDI 音高。`string: 1` 是最细的高音弦。`fret` 相对变调夹计数；实际音高为 `tuning[6 - string] + capo + fret`。例如此例的 6 弦 0 品，基础定弦 D2，加上 Capo 2，实际为 E2。

`beats` 以四分音符为 1，支持 0.125 的倍数，空 `notes` 表示休止，同一事件多个音表示和弦。4/4 每小节为 4，6/8 每小节为 3。谱面按比例显示拍点及常见时值，短音按拍分组连杠（复拍子按三八分音符分组），支持单/双附点。不规则时值直接标出拍数；支持技巧连接线与跨小节连接；任意长时值的拆分延音记谱尚未实现。

JSON 技巧字段（可选）：

泛音使用音符 `technique: "harmonic"`、`fret: 12`（相对变调夹的八度节点），可加 `harmonicAttack: "tap"` 表示拍泛音，省略或 `"pluck"` 为拨弦泛音。不把 5 / 7 品泛音当作普通按弦音高处理；当前只支持 12 品节点。

| 字段                                             | 含义                                                     |
| ------------------------------------------------ | -------------------------------------------------------- |
| 谱子 `letRing: true`                             | 持续共鸣，直到同弦新动作或休止制音                       |
| 音符 `link: "hammer" / "pull" / "slide" / "tie"` | 与同弦上一个音连接；校验击勾弦方向、滑音品位与延音同音高 |
| 事件 `strum: "down" / "up"`                      | 6→1 / 1→6 逐弦扫奏，谱面箭头分别朝上 / 下                |
| 事件 `palmMute: true`                            | 掌根制音                                                 |
| 事件 `percussion: "body-tap" / "string-slap"`    | 拍琴身 / 拍弦，可与和弦同时存在，也可独立出现            |

技巧字段随内置曲目打包并在 JSON 导出中保留。直接从连奏中间开始播放时会发出被点击的目标音；连续播放时保留前后连接。

## 实现与边界

采用 TypeScript + Vite，无运行时框架依赖。Web Audio `AudioContext.currentTime` 配合短间隔前瞻调度用于播放，YIN 基频检测用于调音；跟奏结合 FFT 频谱、基频检测和新起音判定。浏览器测试通过虚拟麦克风注入带泛音的 E2 及当前曲目开头的和弦/拨弦 WAV，验证实际 `getUserMedia → AnalyserNode → 音高检测 → 界面/跟奏` 链路，以及和弦延音不误跳、重新拨弦能推进。

当前是可运行 MVP，以下能力未实现：

- 通用图片/PDF 的谱面与调弦标记 OCR，以及 Guitar Pro/MusicXML 导入；曲库中的 PDF 曲目是人工录入，调弦标记从内置结构化数据读取。
- 逐弦指法、完整和弦配置、多声部和技法质量的精确评分。和弦跟奏只匹配主要音高；拍击跟奏只判断新起音，不区分拍琴身与拍弦，也不验证和弦中同时出现的拍击动作。
- 任意距离的演奏转录和随演奏动态变速的伴奏。智能跟奏只在附近 4 个谱位重新定位；节拍跟随以固定 BPM 为准。重复乐句、快速密集音、弱击勾弦和环境串音仍可能产生歧义，节奏偏差是估计值而非专业评分。详见 [跟奏与节奏记录](docs/practice.md)。
- 真实吉他音色采样与演奏录音复刻；当前普通拨弦使用多分音和随时间变化的滤波、包络，技巧按独立动作模型模拟。泛音区分拨弦与拍泛音，使用短触弦瞬态、多个模态和快慢衰减，保留延音，下一次同弦动作或闷音时制音。泛音增加独立立体声混响，可在谱面底部「记号 / 音色」切换干声 / 自然 / 空灵。普通 P.M. 使用独立受阻尼弦模型，保留低频音高与短促触弦声。参见[泛音与音色模型](docs/harmonics.md)。合成参数尚未与原演奏频谱拟合。音高继续按谱面定弦、变调夹与相对品位计算。
- 账号、云端曲库、跨设备同步。曲谱由静态文件提供，浏览器仅保存播放偏好与练习记录。

识别测试覆盖合成音频与浏览器流程，尚未完成真实吉他、不同手机/麦克风、噪声和扬声器串音下的实机验证。调音请单独拨弦并让其他弦静音；真实录音的泛音、环境声和麦克风自动处理仍可能造成误判。
